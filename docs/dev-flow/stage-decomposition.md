# Stage: Decomposition

1. Read the issue, `desc.md` and the specifications.
2. Divide the design into blocks.
3. Write a `<block>.md` file for each block from [template-block.md](template-block.md).
4. Write `plan.md` from [template-plan.md](template-plan.md).
   Put the blocks in the order of execution.

A block is one complete unit of work. It does one complex task.
An agent can do it without help. A reviewer can review it as one unit.
A block is not the smallest possible step and is not very large.

Each block file records who plans, implements and reviews it.
It also records if the block needs more reviewers.
Above the list, `plan.md` can contain a note about priorities and parallel work.

Result: `plan.md` and the block files.
