# Задача 7. Тексты

В этой задаче ты добавляешь в «Лампу» читальню. Экран `texts` показывает список из двух текстов.
Экран `reader` показывает текст по страницам.

## Файлы содержимого

«Файл содержимого» — файл, который показывает экран.
Положи файлы содержимого в каталог `content` каталога BBS.

- Путь в `content` может содержать каталоги, например `xfer/src/crc16.c`.
  Каждая часть пути состоит из латинских букв, цифр, `_`, `.` и `-`.
  Она начинается с буквы, цифры или `_`.
- Файл — текст в UTF-8, не больше 1 МБ. Строка кончается на LF или CR LF.
  Управляющий символ, кроме TAB, — ошибка.
- Расширение задаёт «вид» файла. Регистр не важен:

| Расширение | Вид |
|---|---|
| `.md`, `.markdown` | Markdown |
| `.txt` или без расширения | Простой текст |
| Любое другое расширение | Исходный код |

Создай каталог `content`. Создай файлы `content/lamp.md` и `content/rules.txt`
по разделам «Markdown» и «Простой текст» ниже.

Полные правила: [file-view](../../../specs/file-view.md), раздел 2.

## Экран `texts`

`args` передаёт аргумент экрану из `gosub` или `goto`:

```
[[item]]
key = "1"
do = "gosub reader"
args = { file = "lamp.md" }
```

- Экран `reader` получает аргумент `file` со значением `lamp.md`.
  Поле `{arg.file}` даёт это значение.
- Имя аргумента состоит из строчных латинских букв, цифр и `_` и начинается с буквы.
  В значении не может быть `{` и управляющих символов.
- `gosub` и `goto` передают ровно те аргументы, которые использует их экран.
  Недостающий или лишний аргумент — ошибка.

Полные правила: [bbt-format](../../../specs/bbt-format.md), раздел 8.5.

## Файловый экран `reader`

У «файлового экрана» во front matter есть ключ `file`.
`file` задаёт файл содержимого: путь в `content` или ровно один токен `{arg.<name>}`.

```
+++
file = "{arg.file}"
margin = [7, 2]
```

- `{>file}` — «область файла»: место текста. Это единственный текст в своей строке.
  У файлового экрана ровно один `{>file}`, в его собственном теле: не во фрагменте и не в `{#if}`.
- `margin = [left, right]` задаёт пустые клетки слева и справа от области файла.
  `[7, 2]` даёт столбцы 8–78: столбец текста «Лампы». Без `margin` текст начинается со столбца 1.
  `left + right` должно быть меньше минимальной ширины экрана.
- Строки до `{>file}` — «строки сверху». Строки после него — «строки снизу».
  Область файла занимает остальные строки терминала.
  При 24 строках у `reader` 8 строк сверху и 5 строк снизу, поэтому в области файла 11 строк.
- BBS режет текст на страницы по размеру области файла. У файлового экрана нет строки More:
  другие страницы показывают его пункты.
- Последняя строка `reader.bbt` пустая. Она даёт пустую строку 24 и оставляет нижнюю линию в строке 21.
  Без неё в области файла 12 строк, и нижняя линия уходит в строку 22.
- Если строк меньше 14, BBS обрезает каждую страницу по последней строке терминала.
  Если строк меньше 13, строки клавиш не видно.

Полные правила: [file-view](../../../specs/file-view.md), разделы 3, 3.1 и 3.2.

## Действия со страницами

| `do` | Действие |
|---|---|
| `page next` | Показать следующую страницу. На последней странице показать её снова. |
| `page prev` | Показать предыдущую страницу. На первой странице показать её снова. |
| `page first` | Показать первую страницу. |
| `page last` | Показать последнюю страницу. |

- Действие `page` работает только в файловом экране и в экране-списке (задача 8).
- `when = "not file.last"`: `Space` работает на каждой странице, кроме последней.
- `when = "file.page > 1"`: `B` работает со страницы 2.
- Строка клавиш показывает клавишу, только когда её пункт работает: `{#if item.SPACE}...{/if}`.
  Поэтому на странице 1 нет `B`, а на последней странице нет `Space`.

Полные правила: [file-view](../../../specs/file-view.md), раздел 3.3,
и [menu-nav](../../../specs/menu-nav.md), раздел 5.1.

## Поля файла

| Поле | Значение |
|---|---|
| `file.title` | Ключ `title` из front matter. Иначе текст первого заголовка уровня 1. Иначе имя файла, например `rules.txt`. |
| `file.page` | Номер страницы, с 1. |
| `file.pages` | Число страниц. |
| `file.last` | Истинно на последней странице. Используй его только в условии. |
| `file.section` | Текст последнего заголовка уровня 1 или 2 в начале страницы или выше. Иначе пусто. |
| `file.minutes` | Время чтения в минутах. |
| `meta.<key>` | Ключ `<key>` из front matter. Иначе пусто. |

- Эти поля работают только в файловом экране.
- Время чтения — число слов, делённое на 200, с округлением вверх, не меньше 1.
  В Markdown BBS считает слова текста, без front matter и адресов.
  В простом тексте и исходном коде BBS считает слова строк, которые показывает экран.
- Строка 7 экрана `reader` показывает автора, только когда в файле есть `author`:
  `{#if meta.author != ""}{meta.author}  ∙  {/if}`.
- Нижняя линия показывает номер страницы в центре:
  `{~─} {!dim}{file.page}/{file.pages}{!line} {~─}`. Два растягивающих токена делят свободные клетки.
  При нечётном числе свободных клеток правый токен получает на одну клетку больше.

Полные правила: [file-view](../../../specs/file-view.md), разделы 3.4 и 3.5.

`examples/lamp/ru/screens/reader.bbt`:
```
+++
file = "{arg.file}"
margin = [7, 2]
[[item]]
key = "SPACE"
do = "page next"
when = "not file.last"
[[item]]
key = "B"
do = "page prev"
when = "file.page > 1"
[[item]]
key = "ESC"
do = "back"
+++
{>_head}
       {!title}{file.title}{!}
       {!dim}{#if meta.author != ""}{meta.author}  ∙  {/if}{file.minutes} мин{!}

{>file}

  {!line}{~─} {!dim}{file.page}/{file.pages}{!line} {~─}{!}  

    {#if item.SPACE}{!key}Space{!}  {!dim}дальше{!}   {/if}{#if item.B}{!key}B{!}  {!dim}пред.{!}   {/if}{!key}Esc{!}  {!dim}список{!}

```

## Markdown

BBS показывает Markdown: CommonMark с таблицами GitHub.

| Markdown | Вид | Стиль |
|---|---|---|
| Абзац | Текст. Он переносится на краю области файла. | `normal` |
| `# Заголовок` | Текст. | `md_h1` |
| `## Заголовок` | Текст. | `md_h2` |
| `### Заголовок` – `###### Заголовок` | Текст. | `md_h3` |
| `**жирный**` | Текст. | `md_strong` |
| `*выделение*` | Текст. | `md_em` |
| `` `код` `` | Текст. | `md_code` |
| `- пункт` | `∙ пункт`. Во вложенном списке `-`. | `md_mark`, вложенный `md_frame` |
| `1. пункт` | `1. пункт` | `md_mark`, вложенный `md_frame` |
| `> цитата` | `│ цитата` | черта `md_mark`, текст `md_em` |
| Блок кода | `│ код`. Длинная строка не переносится: её кончает `...`. | черта `md_frame`, код `md_code` |
| `---` | `∙   ∙   ∙` | `md_mark` |
| Таблица | Столбцы через 2 пробела. Под заголовком линия `─`. | заголовок `md_strong`, линия `md_frame` |
| `[текст](https://...)` | Текст и номер сноски, например `[1]`. | `md_link`, номер `md_dim` |
| `![текст](picture.png)` | Текст, как у ссылки. | `md_link` |
| `<https://...>` | Адрес. | `md_link` |
| HTML | Текст как есть. | `normal` |

- Другие расширения GitHub показываются как текст, например `~~текст~~`.
- У ссылки с адресом со схемой, например `https:`, есть сноска.
  После последнего блока BBS показывает сноски: `[1] <адрес>` в стиле `md_dim`.
  У ссылки без схемы, например на другой файл Markdown, сноски нет.
  У адреса в `<` и `>` сноски нет.
- Заголовок уровня 1 начинает новую страницу. Поэтому в `lamp.md` нет заголовка уровня 1.
- Заголовок остаётся на одной странице с первой строкой следующего блока.
- Страница не начинается с пустой строки.

«Front matter» файла Markdown даёт поля `meta.*`. Запиши его на TOML между строками `+++`:

```
+++
title = "Как зажигали лампы"
author = "Анна Линд"
+++
```

- Front matter начинается с первой строки файла.
- Каждый ключ с одним значением даёт поле `meta.<key>`. Ключ `title` даёт ещё и `file.title`.
- Первая строка `+++` без закрывающей строки — ошибка (задача 10).
- Front matter на YAML между строками `---` — ошибка.

Полные правила: [file-view](../../../specs/file-view.md), раздел 5.

`examples/lamp/ru/content/lamp.md`:
```
+++
title = "Как зажигали лампы"
author = "Анна Линд"
+++

Люди зажгли первые лампы задолго до того, как написали первые слова.
Тысячи лет лампа давала маленький, *ровный* свет.
```

## Стили текста

Стили `md_*` задают цвета текста. В «Лампе» они есть в `screens/screens.toml` (задача 6):

- `md_h1` и `md_strong` как `title`: светло-персиковые и жирные;
- `md_h2` и `md_mark` как `orn`: оранжевые. `md_mark` — маркер списка, черта цитаты и разделитель;
- `md_h3`, `md_em` и `md_link` светло-коричневые. Ссылка подчёркнута: это не клавиша;
- `md_code` светло-оливковый;
- `md_frame` как `line`, а `md_dim` как `dim`.

Тема без стилей `md_*` использует стили по умолчанию: белые заголовки, жёлтый маркер списка.
`[theme.256]` и `[theme.16]` «Лампы» задают остальные стили `md_*` для каждой глубины.
Ссылка берёт стиль своего имени на той же глубине.
При 16 цветах выделение выглядит как текст.

Полные правила: [file-view](../../../specs/file-view.md), раздел 4.

## Исходный код

Исходный код показывает каждую строку в стиле `md_code`. Длинная строка не переносится: её кончает `...`.
TAB переходит к следующей клетке, кратной 8.

Экран может показать постоянный файл или его часть:

```
+++
file = "src/lamp.c"
lines = [4, 8]
numbers = true
margin = [7, 2]
[[item]]
key = "ESC"
do = "back"
+++
{>file}
```

- `lines = [first, last]` показывает строки с `first` по `last`.
- `numbers = true` показывает номера строк в стиле `md_dim`.
- `lines` и `numbers` работают только для простого текста и исходного кода.

Область файла:

```text
       4 int main(void)
       5 {
       6         puts("The light stays on.");
       7         return 0;
       8 }
```

Полные правила: [file-view](../../../specs/file-view.md), раздел 6.

## BBS на двух языках

BBS может показывать экраны и тексты на нескольких языках.
Пользователь выбирает язык. BBS помнит выбор до конца сессии.

Каждая таблица `[lang.<code>]` в `screens/screens.toml` добавляет язык.
Код — две или три строчные латинские буквы, например `en` или `ru`.
`[screen] lang` — язык в начале сессии. По умолчанию `en`.

```toml
[screen]
lang = "en"

[lang.en]

[lang.ru]
more = "    дальше ∙ любая клавиша"
```

`more` в таблице языка задаёт строку More этого языка.
Без него строка More — это `[screen] more`, а без него — `-- More --`.

Положи файлы языка в каталог с именем его кода:

```
screens/
  screens.toml
  main.bbt        выбор языка
  _logo.bbt       один логотип для всех языков
  en/menu.bbt     меню на английском
  ru/menu.bbt     меню на русском
content/
  en/lamp.md
  ru/lamp.md
```

BBS сначала ищет файл на языке сессии, потом в общем каталоге.
Пример: на языке `ru` экран `menu` — это `screens/ru/menu.bbt`, а если его нет — `screens/menu.bbt`.
Так же BBS ищет фрагмент, арт и файл содержимого, в том числе из общего экрана.
Файл без текста, например логотип, лежит в `screens/` один раз для всех языков.

Общий экран `main` спрашивает язык:

```
+++
[[item]]
key = "E"
do = "gosub en/menu"
[[item]]
key = "R"
do = "gosub ru/menu"
+++
{>_logo}
E  English   R  Русский
```

`gosub ru/menu` ставит язык `ru` и показывает экран `menu` на этом языке.
В стеке лежит только имя `menu`. Поэтому `Esc` с `back` в меню снова показывает `main`.

Действие `lang <code>` меняет язык на любом экране.
BBS снова показывает тот же экран, уже на новом языке. Файловый экран остаётся на своей странице.

```
[[item]]
key = "L"
do = "lang en"
```

Поле `session.lang` — язык сессии:

```
{#if session.lang == "ru"}Язык: русский{#else}Language: English{/if}
```

- В каждом языке должны быть одни и те же экраны с одними и теми же аргументами.
  `velourbbs check` проверяет экраны каждого языка.
  Пример: `screens/ru/news.bbt:1:1: no screen "news" (language "en")`.
- Ошибка общего файла, которую находят не все языки, кончается языком.
  Пример: `screens/about.bbt:6:6: item "M": do: unknown screen "menu" (language "de")`.
- `velourbbs preview menu --set session.lang=ru` показывает экран `menu` на русском.

Полные правила: [session-language](../../../specs/session-language.md), разделы 2–6,
и [menu-nav](../../../specs/menu-nav.md), раздел 4.

## Проверь страницы

Экрану `reader` нужен аргумент `file`. Передай его через `--set`:

```
velourbbs preview reader --set arg.file=lamp.md
```

Команда выводит cell dump каждой страницы текста, одну за другой.
Без `--set` `velourbbs preview reader` выводит ошибку `missing argument "file" of screen "reader"`.

`--keys` показывает страницы. Начни с `texts`: `1` открывает текст в `reader`, `Esc` возвращает на `texts`:

```
velourbbs preview texts --keys 1,SPACE,SPACE,B,ESC
```

```
screen texts
page 1 80x24 fill spaces
...
key 1
screen reader
page 1 80x24 fill spaces
...
key SPACE
page 2 80x24 fill spaces
...
key SPACE
page 3 80x24 fill spaces
...
key B
page 2 80x24 fill spaces
...
key ESC
screen texts
page 1 80x24 fill spaces
...
```

## Результат

- `velourbbs check` ничего не выводит.
- `velourbbs preview reader --set arg.file=lamp.md` выводит три страницы. Страница 1 — экран выше, с `1/3` на нижней линии.
- `velourbbs preview reader --set arg.file=lamp.md --keys SPACE,SPACE` выводит страницу 3. Её строка клавиш — `B  пред.   Esc  список`.
- В telnet-клиенте `R` показывает список, `1` показывает текст, `Space` и `B` листают страницы,
  `Esc` возвращает к списку.
