# Руководство по BBT

Это руководство учит писать экраны Velour BBS.
Оно для художника и автора экранов.
Нужны текстовый редактор, терминал и telnet-клиент.

## Введение

### Каталог BBS

«Каталог BBS» содержит файлы одной BBS:

| Файл | Содержимое |
|---|---|
| `bbs.toml` | Настройки хоста. В этом руководстве файл пустой. |
| `screens/screens.toml` | Настройки экранов: ширина, стили и другие значения. |
| `screens/<name>.bbt` | «Экран»: текстовый файл. BBS показывает его пользователю. |
| `screens/_<name>.bbt` | «Фрагмент»: часть экрана. Его имя начинается с `_`. |

Запускай каждую команду `velourbbs` в каталоге BBS.

### Программа `velourbbs`

Собери программу с помощью Go. В репозитории исходного кода Velour BBS выполни:

```
go build ./cmd/velourbbs
```

Команда создаёт файл `velourbbs` (`velourbbs.exe` в Windows).
Положи его в каталог из `PATH`. Или попроси программу у сисопа.

### Пример

Задачи строят пример BBS «Лампа». Его файлы лежат в
[`examples/lamp/ru/`](../../../examples/lamp/ru/).

- Строка с путём и двоеточием показывает целый файл примера.
  Пример: `` `examples/lamp/ru/screens/main.bbt`: ``.
  Запиши этот файл в свой каталог BBS без `examples/lamp/ru/`: `screens/main.bbt`.
- Остальные блоки показывают часть файла, команду или вывод.

Каждая задача ссылается на спецификации с полными правилами.

## Задача 1. Каталог BBS

1. Создай каталог, например `mybbs`. Создай в нём каталог `screens`.
2. Создай пустой файл `bbs.toml`.
3. Создай `screens/main.bbt` с таким текстом:

```
+++
[[item]]
key = "G"
do = "logoff"
+++
Привет! Это моя BBS.

G  до свидания
```

Строки между двумя строками `+++` — это «front matter». Он задаёт меню экрана.
Здесь в меню один пункт: клавиша `G` завершает сеанс (`logoff`).
У экрана должен быть хотя бы один пункт. Только у экрана `goodbye` нет пунктов (задача 4).
Остальные строки — это «тело»: текст экрана.
BBS показывает экран `main` первым.

### Проверь файлы

Выполни:

```
velourbbs check
```

Если файлы верны, команда ничего не выводит.
Иначе она выводит по строке на каждую ошибку или предупреждение:

```
screens/_x.bbt:1:1: warning: no screen uses this file
screens/main.bbt:2:1: item "G": do: unknown action "logof"
```

Строка содержит файл, номер строки, номер столбца и сообщение.
Ошибка в пункте указывает строку 2: первую строку front matter.
У предупреждения перед сообщением стоит `warning:`. Предупреждение не останавливает BBS. Ошибка останавливает.
Полные правила: [screen-render](../../specs/screen-render.md), раздел 3.1.

### Посмотри на экран

Выполни:

```
velourbbs preview main
```

Команда выводит «cell dump» экрана для терминала 80 столбцов на 24 строки:

```
page 1 80x24 fill none
|Привет! Это моя BBS.                                                            |
|                                                                                |
|G  до свидания                                                                  |
styles
1: 1-80 7/0
2: 1-80 7/0
3: 1-80 7/0
```

- Первая строка содержит страницу, размер терминала и заполнение строк под экраном.
- Каждая строка экрана стоит между двумя `|`.
- Каждая строка после `styles` содержит номер строки и «отрезки стилей» этой строки.
  Отрезок содержит первый столбец, последний столбец и стиль. `7/0` — светло-серый на чёрном.

Для других размеров используй `--size`, например `velourbbs preview main --size 132x43`.
Полные правила: [screen-render](../../specs/screen-render.md), разделы 3.2 и 3.3.

### Посмотри на экран в telnet-клиенте

1. Выполни `velourbbs serve`. Сервер слушает порт 2323.
2. Подключи telnet-клиент к `localhost`, порт 2323. Используй PuTTY или Tera Term:
   они показывают UTF-8 и 256 цветов. SyncTERM и NetRunner не показывают UTF-8.
   В PuTTY выбери тип соединения «Telnet».
   Установи «Close window on exit» в «Never»: иначе PuTTY закрывает окно в конце сеанса.
3. Нажми `G`, чтобы завершить сеанс.

Сервер читает файлы только при запуске. После каждого изменения файла
останови сервер клавишами Ctrl+C и запусти снова.
Полные правила: [telnet-term](../../specs/telnet-term.md), разделы 3 и 6.

### Результат

- `velourbbs check` ничего не выводит.
- Telnet-клиент показывает две строки текста. `G` завершает сеанс.

## Задача 2. Первый экран

В этой задаче ты пишешь первый экран «Лампы». Меню остаётся прежним: один пункт `G`. Задача 4 добавляет остальные пункты.

### Ширина и стили

Создай `screens/screens.toml` с таким текстом:

```toml
[screen]
width = [80, 80]
fill = "spaces"

[theme.default]
normal = "#e9dccb/#2a201d"
dim    = "#9e8a7c"
line   = "#8a6a5c"
title  = "#f7c7a3 bold"
key    = "#ffb088 bold"
orn    = "#f2a27e"
```

- `width = [80, 80]` задаёт наименьшую и наибольшую ширину экрана.
  Поэтому экран всегда шириной 80 столбцов. На более широком терминале BBS ставит его по центру.
  На более узком терминале она обрезает строки.
- `fill = "spaces"` заполняет строки терминала под экраном стилем `normal`.
- `[theme.default]` — это «тема»: она даёт имя каждому стилю.
  Стиль — это цвет текста, цвет фона после `/` и атрибуты, например `bold`.
  Цвет — это `#rrggbb` или число от 0 до 255.
- `normal` — стиль фона экрана и обычного текста.
  Стиль без цвета фона берёт фон из `normal`.

Полные правила: [screens-toml](../../specs/screens-toml.md), разделы 3.1 и 3.2,
и [bbt-format](../../specs/bbt-format.md), разделы 6.1–6.3, 6.5 и 7.

### Текст и токены стиля

- Каждая строка тела — одна строка экрана. Пустая строка тела — пустая строка экрана.
  Строка шире экрана переносится по пробелу на несколько строк экрана.
- Пробелы в начале строки сохраняются.
- `{!name}` включает стиль `name` из темы. `{!}` снова включает стиль `normal`.
  Стиль действует и на следующих строках, до следующего токена стиля.

Пример:

```
       {!title}Лампа{!}  {!orn}☼ {!dim}BBS при свете лампы{!}
```

Эта строка показывает слово «Лампа» светло-персиковым жирным, в стиле `title`,
солнце `☼` тёплым оранжевым, в стиле `orn`, и подзаголовок серо-коричневым, в стиле `dim`.

### Экран

Перепиши `screens/main.bbt` с таким текстом:

```
+++
[[item]]
key = "G"
do = "logoff"
+++

  {!line}────────────────────────────────────────────────────────────────────────────{!}

       {!title}Лампа{!}  {!orn}☼ {!dim}BBS при свете лампы{!}

       Добрый вечер. Здесь тихо и тепло.
       Садись поближе к свету.











       {!dim}Свет горит до утра.{!}

  {!line}────────────────────────────────────────────────────────────────────────────{!}

    {!key}G{!}  {!dim}до свидания{!}
```

В экране 23 строки:

```text

  ────────────────────────────────────────────────────────────────────────────

       Лампа  ☼ BBS при свете лампы

       Добрый вечер. Здесь тихо и тепло.
       Садись поближе к свету.











       Свет горит до утра.

  ────────────────────────────────────────────────────────────────────────────

    G  до свидания
```

- Фон тёмно-коричневый. Текст кремовый.
- Две линии коричневые, в стиле `line`. Они занимают столбцы 3–78.
- Заключительная строка «Свет горит до утра.» и слова «до свидания» серо-коричневые, в стиле `dim`.
- Клавиша `G` оранжевая и жирная, в стиле `key`.

PuTTY и Tera Term показывают 256 цветов. Там фон тёмно-серый.
Задача 6 задаёт стили для 256 цветов.

### Результат

- `velourbbs check` ничего не выводит.
- `velourbbs preview main` выводит 23 строки. У строк 2 и 4 такие отрезки стилей:

```
2: 1-2 #e9dccb/#2a201d, 3-78 #8a6a5c/#2a201d, 79-80 #e9dccb/#2a201d
4: 1-7 #e9dccb/#2a201d, 8-12 #f7c7a3/#2a201d bold, 13-14 #e9dccb/#2a201d, 15-16 #f2a27e/#2a201d, 17-35 #9e8a7c/#2a201d, 36-80 #e9dccb/#2a201d
```

- Telnet-клиент показывает экран с тёмным фоном на всех строках.

Сохрани вывод для задачи 3:

```
velourbbs preview main > task2.txt
```

## Задача 3. Шапка

Каждый экран «Лампы» начинается с одних и тех же 5 строк: это «шапка».
Напиши их один раз во фрагменте и подключи фрагмент в каждом экране.

- Фрагмент — это `screens/_<name>.bbt`. У него нет front matter.
- Строка `{>_<name>}` подключает фрагмент: BBS ставит строки фрагмента на её место.
  В этой строке не должно быть другого текста.
- После подключения действует тот же стиль, что и до него.

Полные правила: [bbt-format](../../specs/bbt-format.md), разделы 3.3 и 3.4.

В `screens/main.bbt` замени строки 1–5 одной строкой:

```
+++
[[item]]
key = "G"
do = "logoff"
+++
{>_head}
       Добрый вечер. Здесь тихо и тепло.
```

Перенеси эти 5 строк во фрагмент:

`examples/lamp/ru/screens/_head.bbt`:
```

  {!line}────────────────────────────────────────────────────────────────────────────{!}

       {!title}Лампа{!}  {!orn}☼ {!dim}BBS при свете лампы{!}

```

### Результат

- `velourbbs check` ничего не выводит.
- `velourbbs preview main` выводит то же, что и в задаче 2. Для сравнения выполни:

```
velourbbs preview main > task3.txt
diff task2.txt task3.txt
```

`diff` ничего не выводит. В Windows используй `fc task2.txt task3.txt`.

## Задача 4. Меню с горячими клавишами

### Пункты

Каждый `[[item]]` во front matter — один пункт меню:

```
[[item]]
key = "A"
do = "goto about"
```

- `key` — клавиша: латинская буква, цифра или имя клавиши, например `ESC` или `ENTER`.
  Регистр не важен. Русская буква работает как латинская буква на той же клавише: `ф` — это `A`.
- `do` — действие: `goto <screen>` показывает экран, `logoff` завершает сеанс.
- BBS не показывает пункты. Напиши текст пунктов и строку клавиш в теле.
  Строка клавиш показывает все клавиши экрана.

Полные правила: [bbt-format](../../specs/bbt-format.md), раздел 8,
и [menu-nav](../../specs/menu-nav.md), разделы 3–6.

### Экран `main`

В меню три пункта: `A` ведёт на экран `about`, `T` — на экран `term`,
`G` завершает сеанс.

`examples/lamp/ru/screens/main.bbt`:
```
+++
[[item]]
key = "A"
do = "goto about"
[[item]]
key = "T"
do = "goto term"
[[item]]
key = "G"
do = "logoff"
+++
{>_head}
       Добрый вечер. Здесь тихо и тепло.
       Садись поближе к свету.


         {!key}A{!}   О станции                               {!dim}кто мы{!}

         {!key}T{!}   Твой терминал                           {!dim}размер и цвета{!}

         {!key}G{!}   До свидания                             {!dim}лампа подождёт{!}




       {!dim}Свет горит до утра.{!}

  {!line}────────────────────────────────────────────────────────────────────────────{!}

    {!key}A T G{!}  {!dim}выбор{!}
```

Экран:

```text

  ────────────────────────────────────────────────────────────────────────────

       Лампа  ☼ BBS при свете лампы

       Добрый вечер. Здесь тихо и тепло.
       Садись поближе к свету.


         A   О станции                               кто мы

         T   Твой терминал                           размер и цвета

         G   До свидания                             лампа подождёт




       Свет горит до утра.

  ────────────────────────────────────────────────────────────────────────────

    A T G  выбор
```

Клавиши оранжевые, в стиле `key`. Пояснения справа и слово «выбор» серо-коричневые, в стиле `dim`.

### Экран `about`

Клавиши `Esc` и `Enter` возвращают на `main`:


`examples/lamp/ru/screens/about.bbt`:

Клавиши `Esc Enter` оранжевые, в стиле `key`. Слово «назад» серо-коричневое, в стиле `dim`.

## Задача 5. Поля и условия

В этой задаче ты пишешь экран `term`. Он показывает, что BBS знает о терминале пользователя.

### Поля

«Поле» — это токен, который BBS заменяет значением:

```
       {!dim}Размер{!}   {term.cols}×{term.rows}
```

На терминале 80 столбцов на 24 строки эта строка показывает `Размер   80×24`.

| Поле | Значение |
|---|---|
| `term.cols` | Число столбцов терминала, от 20 до 255. |
| `term.rows` | Число строк терминала, от 10 до 100. |
| `term.colors` | Глубина цвета: `16`, `256` или `16777216` (задача 6). |
| `term.type` | Тип терминала, который передаёт клиент, в нижнем регистре. Без типа — `ansi`. |
| `term.charset` | Всегда `utf-8`. |

- Поле без пробелов в фигурных скобках берёт ширину своего значения.
- У поля с пробелами в фигурных скобках «фиксированная ширина»: ширина токена вместе со скобками.
  BBS дополняет короткое значение пробелами и обрезает конец длинного значения.
  Пробелы после имени выравнивают значение влево. Пробелы перед именем выравнивают его вправо.

```
[{term.type      }]
[{      term.type}]
```

Каждый токен шириной 17 клеток. BBS показывает:

```text
[xterm            ]
[            xterm]
```

- `{` начинает токен, когда за ней идёт латинская буква, пробел, `#`, `/`, `!`, `>` или `@`.
  `{{` даёт простую `{`. Пример: `Напиши {{name} здесь.` показывает `Напиши {name} здесь.`

### Поля сессии и BBS

Другие поля показывают данные сессии и BBS:

```
{bbs.name} {bbs.version}  {bbs.time}
Твой адрес {session.ip}, на связи {session.online}
Сейчас на связи {bbs.sessions}, BBS работает {bbs.uptime}
```

| Поле | Значение |
|---|---|
| `session.ip` | Адрес пользователя. Пример: `203.0.113.7`. |
| `session.online` | Время от подключения пользователя: `чч:мм`, от 24 часов `<д>d чч:мм`. |
| `bbs.name` | Ключ `name` таблицы `[bbs]` в `bbs.toml`. По умолчанию `Kind Brothers BBS`. |
| `bbs.version` | Версия `velourbbs`, например `v1.2.0`. Сборка не из тега релиза даёт `dev`. |
| `bbs.sessions` | Сколько пользователей на связи сейчас, вместе с этим пользователем. |
| `bbs.time` | Дата и время сервера. |
| `bbs.uptime` | Время от запуска `velourbbs serve`, в форме `session.online`. |

- BBS берёт значения, когда показывает экран. Значение на экране не меняется
  до следующего экрана.
- `[screen] time` в `screens/screens.toml` задаёт форму `bbs.time` через опорное время Go
  `2006-01-02 15:04:05`. По умолчанию `"2006-01-02 15:04"`. Пример для `16.11.2026 15:04`:

```toml
[screen]
time = "02.01.2006 15:04"
```

- У `velourbbs preview` нет сессии. Он показывает `127.0.0.1`, `00:00`, `1` пользователя
  и время `2006-01-02 15:04:05`. `--set` меняет значение, например
  `--set bbs.sessions=12`.

Полные правила: [session-fields](../../specs/session-fields.md), разделы 2–4.

### Алиасы

`[fields]` в `screens/screens.toml` даёт полю короткое имя — «алиас»:

```toml
[fields]
w = "term.cols"
```

Тогда `{w}` показывает число столбцов терминала. Короткий алиас помогает в арте (задача 7).

Полные правила: [bbt-format](../../specs/bbt-format.md), разделы 3.3 и 4,
и [screens-toml](../../specs/screens-toml.md), раздел 3.3.

### Условия

```
{#if term.colors == 16777216}16 млн{#else}{term.colors}{/if}
```

Этот текст показывает `16 млн`, когда терминал показывает 16777216 цветов. Иначе он показывает число.

- `{#if <условие>}` показывает текст до `{#else}` или `{/if}`, когда условие истинно.
- `{#else}` показывает текст до `{/if}`, когда условие ложно. `{#else}` не обязателен.
- Блок может занимать несколько строк и содержать другие блоки.
  Каждому `{#if}` нужен свой `{/if}` в том же файле.
- Строка с `{#if}`, `{#else}` или `{/if}` не даёт строки экрана, когда на ней остались только пробелы.
- Операторы: `==`, `!=`, `<`, `<=`, `>` и `>=`.
  Числовое поле принимает число и любой оператор.
  Текстовое поле принимает текст в двойных кавычках и только `==` или `!=`: `term.type == "xterm"`.
- `and` и `or` соединяют условия. `and` связывает сильнее. Скобок нет.

Полные правила: [bbt-format](../../specs/bbt-format.md), разделы 5 и 6.2.

### Пункты с условием

`when` даёт пункту условие. Когда условие ложно, пункт не работает.
`{#if item.<KEY>}` истинно, когда пункт `<KEY>` работает. Так текст пункта и его клавиша согласованы:

```
+++
[[item]]
key = "W"
do = "goto wide"
when = "term.cols >= 132"
[[item]]
key = "G"
do = "logoff"
+++
{#if item.W}W  широкий экран{/if}
G  до свидания
```

На терминале шириной 132 столбца и больше экран показывает `W  широкий экран`, и `W` работает.
На более узком терминале эта строка не даёт строки экрана, и BBS игнорирует `W`.
`not item.W` истинно, когда пункт не работает.

Полные правила: [bbt-format](../../specs/bbt-format.md), раздел 8.2.

### Экран `term`

Перепиши `screens/term.bbt` с таким текстом. Он заменяет копию `about.bbt` из задачи 4.

`examples/lamp/ru/screens/term.bbt`:

```
[[item]]

  {!line}────────────────────────────────────────────────────────────────────────────{!}

    {!key}Esc Enter{!}  {!dim}назад{!}
```

Экран для терминала 80 столбцов на 24 строки:

- `velourbbs preview term --set term.type=ansi` выводит `Цветов   16` и `Тип      ansi`.

## Задача 6. Глубина цвета

### Глубина цвета терминала

Терминал показывает 16, 256 или 16777216 цветов: это его «глубина цвета».
BBS находит глубину по типу терминала, который передаёт клиент.
Глубину даёт первая строка таблицы, под которую подходит тип:

| Тип терминала | Глубина |
|---|---|
| Кончается на `-direct`, или содержит `truecolor` или `24bit` | 16777216 |
| Содержит `256color` | 256 |
| Кончается на `-16color` или `-8color`, или равен `ansi`, `dumb`, `vt52`, `vt100`, `vt102`, `vt220`, `vt320`, `rxvt`, `xterm-color`, `eterm-color` или `cygwin` | 16 |
| Любой другой тип, например `xterm` | 256 |

- Клиент без типа получает `ansi`, то есть 16 цветов.
- PuTTY и Tera Term передают `xterm`, то есть 256 цветов.

BBS заменяет каждый цвет ближайшим цветом этой глубины.
При 256 цветах кремовый текст `#e9dccb` становится нейтральным серым 253, и экран теряет тепло.
Поэтому подбирай цвета для каждой глубины вручную.
Номера 16–255 — это цвета палитры xterm на 256 цветов.
Номера 0–15 — это цвета VGA из [telnet-term](../../specs/telnet-term.md), раздел 7.3.

Полные правила: [telnet-term](../../specs/telnet-term.md), разделы 6 и 7.3.

### Темы глубины

```toml
[theme.256]
normal = "223/235"
title  = "230 bold"

[theme.16]
normal = "7/0"
title  = "15 bold"
```

- «Тема глубины» даёт другие стили для одной глубины.
  `[theme.256]` — для 256 цветов. `[theme.16]` — для 16 цветов.
- Стиль темы глубины заменяет стиль с тем же именем из `[theme.default]`.
  Остальные стили остаются.
- В теме глубины могут быть только `normal`, `more` и имена из `[theme.default]`.
- Для 16 цветов используй номера 0–15. Для 256 цветов используй номера 16–255.

Полные правила: [screens-toml](../../specs/screens-toml.md), раздел 3.2.

### Строка More

Если у экрана больше строк, чем у терминала, BBS показывает его по страницам. Каждая страница, кроме последней,
кончается «строкой More». Пользователь нажимает любую клавишу и видит следующую страницу.
Пункты на строке More не работают.

```toml
[screen]
more = "    ещё ∙ любая клавиша"
```

`more` задаёт текст строки More. Без `more` текст — `-- More --`.
Стиль `more` задаёт её цвета.
С файлом `screens/screens.toml` ниже, для терминала в 20 строк, экран `about` занимает две страницы:

```
velourbbs preview about --size 80x20
```

```
page 1 80x20 fill spaces
...
|    ещё ∙ любая клавиша                                                         |
styles
...
page 2 80x20 fill spaces
...
```

Страница 1 содержит строки экрана 1–19 и строку More. Страница 2 содержит строки 20–23.

Полные правила: [bbt-format](../../specs/bbt-format.md), раздел 6.4,
и [menu-nav](../../specs/menu-nav.md), раздел 5.

### Файл `screens.toml`

Перепиши `screens/screens.toml` с таким текстом:

`examples/lamp/ru/screens/screens.toml`:
```
[screen]
width = [80, 80]
more = "    ещё ∙ любая клавиша"
fill = "spaces"

[theme.default]
normal = "#e9dccb/#2a201d"
dim    = "#9e8a7c"
line   = "#8a6a5c"
title  = "#f7c7a3 bold"
key    = "#ffb088 bold"
orn    = "#f2a27e"
more   = "#9e8a7c"

[theme.256]
normal = "223/235"
dim    = "137"
line   = "95"
title  = "230 bold"
key    = "216 bold"
orn    = "216"
more   = "137"

[theme.16]
normal = "7/0"
dim    = "8"
line   = "8"
title  = "15 bold"
key    = "15 bold"
orn    = "7"
more   = "8"
```

- При 256 цветах фон тёмно-серый (235), текст кремовый (223), а не серый (253).
- При 16 цветах экран серый: чёрный фон, светло-серый текст,
  тёмно-серые `dim` и `line`, белые `title` и `key`.

### Посмотри на каждую глубину

`velourbbs preview` использует тип `xterm`, то есть 256 цветов. Другую глубину задай через `--set`:

```
velourbbs preview main --set term.colors=16
velourbbs preview main --set term.type=vt100
```

Обе команды показывают экран со стилями `[theme.16]`.
В cell dump цвета темы такие, как ты их написал.
Ближайшие цвета своей глубины показывает только telnet-клиент.

### Результат

- `velourbbs check` ничего не выводит.
- `velourbbs preview main` выводит строку 4 со стилями `[theme.256]`:

```
4: 1-7 223/235, 8-12 230/235 bold, 13-14 223/235, 15-16 216/235, 17-35 137/235, 36-80 223/235
```

- `velourbbs preview main --set term.colors=16` выводит строку 4 со стилями `[theme.16]`:

```
4: 1-7 7/0, 8-12 15/0 bold, 13-16 7/0, 17-35 8/0, 36-80 7/0
```

- PuTTY показывает тёмно-серый фон и кремовый, а не серый текст.
  В PuTTY установи Connection > Data > «Terminal-type string» в `vt100` и подключись снова:
  PuTTY показывает серый экран в 16 цветах.
  Потом верни в «Terminal-type string» значение `xterm`.

## Задача 7. Арт

«ANSI-арт» — это картинка из символов и цветов.
В этой задаче ты показываешь арт на экране. Используй новый каталог BBS, например `myart`.
Файлы лежат в [`examples/art/`](../../../examples/art/). Запиши каждый файл без `examples/art/`.
Тексты этого примера на английском.

1. Создай каталог `myart` и в нём каталог `screens`.
2. Скопируй файл `examples/art/screens/lamp.ans` из репозитория исходного кода
   в `myart/screens/lamp.ans`. Или попроси файл у сисопа.
   Руководство не показывает этот файл: в нём escape-последовательности.

### Вставка арта

```
{>lamp.ans}
```

- `{><name>.ans}` показывает арт `screens/<name>.ans`. В этой строке не должно быть другого текста.
- Каждая строка арта начинается у левого края экрана.
- Арт не меняет стиль текста после него.
- BBS обрезает арт шире экрана.
  `velourbbs check` предупреждает, когда арт шире наибольшей ширины экрана.

Полные правила: [bbt-format](../../specs/bbt-format.md), разделы 3.4 и 6.2.

### Файлы

`examples/art/bbs.toml`:
```
```

Стиль `key` задан номером из 256 цветов:

```toml
key    = "215 bold"
```

Оранжевый 215 остаётся тёплым и при 16 цветах: BBS заменяет его ближайшим номером 0–15.

`examples/art/screens/screens.toml`:
```
[theme.default]
normal = "223/235"

```

`examples/art/screens/main.bbt`:
```
+++
width = [40, 40]
fill = "spaces"
[[item]]

+++

```

- Арт шириной 40 столбцов. `width = [40, 40]` во front matter делает этот экран
  шириной 40 столбцов.
- Ключи `width`, `align`, `valign` и `fill` во front matter задают размещение одного экрана.
  В `[screen]` файла `screens/screens.toml` они задают размещение всех экранов.
- Здесь в `screens/screens.toml` нет `[screen]`. Поэтому у экрана `align = "center"` по умолчанию:
  на терминале шириной 80 столбцов BBS ставит экран по центру.

Экран:

```text

          ▄██████████████████▄
       ░▒▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▒░
          ░░▒▒▒▒▒▒ ██ ▒▒▒▒▒▒░░

            ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀

```

- Фон тёмно-серый. Абажур лампы оранжевый с кремовым верхом.
  Свет под ним жёлтый и тёмно-оранжевый.
- Ножка серо-коричневая. Подставка коричневая.
- Слова «lit for» серо-коричневые. Значение поля, «xterm», кремовое.
  Клавиша `G` оранжевая и жирная, в стиле `key`.

### Положение экрана

```
+++
width = [40, 40]
align = "left"
valign = "middle"
+++
```

- `align` — положение на более широком терминале: `"left"`, `"center"` (по умолчанию) или `"right"`.
- `valign` — положение экрана, у которого строк меньше, чем у терминала:
  `"top"` (по умолчанию), `"middle"` или `"bottom"`.

Полные правила: [bbt-format](../../specs/bbt-format.md), разделы 6.1 и 6.5.

### Поле в арте

Строка 12 файла `lamp.ans` содержит текст `lit for {term.type    }`.
BBS находит поле в арте и ставит значение на его место.

- Поле занимает клетки своего токена: здесь 15 клеток. BBS обрезает более длинное значение.
- Пробелы перед именем выравнивают значение вправо. Иначе значение выравнивается влево.
- У всех клеток токена должен быть один цвет фона.
  У всех его символов, кроме пробелов, должен быть один цвет текста.
  Иначе `velourbbs check` выводит ошибку (задача 8).
- Значение берёт цвета первого символа токена.
- В арте могут быть только поля: без токенов стиля, условий и подключений.
  Короткий алиас (задача 5) даёт короткое поле, например `{w}`.

Полные правила: [art-format](../../specs/art-format.md), раздел 4.

### Арт для малых терминалов

Экран может показывать другое содержимое на узком терминале. Пример с артом шириной 80 столбцов:

```
+++
width = [40, 80]
[[item]]
key = "G"
do = "logoff"
+++
{#if term.cols < 80}
{>_main_small}
{#else}
{>main.ans}
{/if}
```

На терминале меньше 80 столбцов экран показывает фрагмент `screens/_main_small.bbt`:
текст или арт меньшего размера.

Полные правила: [bbt-format](../../specs/bbt-format.md), раздел 6.1.

### Новый арт

BBS читает арт только в «плоской форме». `velourbbs art import` переводит файл
редактора арта в плоскую форму.

1. Нарисуй арт в одном из этих редакторов. Сохрани его с настройками по умолчанию:
   - Moebius 1.0.29: Save (`.ans`);
   - icy_draw 0.6.2: Export в `.ans`;
   - PabloDraw 3.3.14-beta: Save as ANSI (`.ans`).
2. Храни этот «исходный файл» вне `screens/`, например в `art/logo.ans`.
3. Переведи его:

```
velourbbs art import art/logo.ans screens/logo.ans
```

4. Вставь арт строкой `{>logo.ans}`.

Moebius и PabloDraw не открывают плоскую форму. Чтобы изменить арт, правь исходный файл
и переведи его снова.

Полные правила: [art-import](../../specs/art-import.md), разделы 2 и 3.

### Результат

- `velourbbs check` ничего не выводит.
- `velourbbs preview main` выводит экран, как выше, с полосой фона в 20 столбцов с каждой стороны.
- `velourbbs preview main --set term.type=ansi` выводит подпись `lit for ansi`.
- Останови сервер «Лампы». Запусти `velourbbs serve` в `myart`.
  PuTTY показывает лампу в центре окна.

## Задача 8. Ошибки

`velourbbs check` находит ошибки до запуска BBS.
Каждая строка вывода содержит файл, номер строки, номер столбца и сообщение (задача 1).
В арте это номер строки и номер столбца арта.
Эта задача показывает частые ошибки и их исправления.

### `unknown style`

```
screens/about.bbt:10:8: unknown style "titel"
```

Токен стиля `{!titel}` называет стиль, которого нет в теме.
Исправь имя или добавь стиль в `[theme.default]`.

### `token has no "}"`

```
screens/about.bbt:10:35: token has no "}"
```

`{` начинает токен (задача 5). Закрой токен знаком `}` или напиши `{{` для простой `{`.

### `unknown field`

```
screens/about.bbt:11:13: unknown field "term.colours"
screens/about.bbt:14:10: unknown field "note"
screens/term.bbt:14:67: unknown field "item.S"
```

- Это имя — не поле и не алиас (задача 5). Исправь имя.
- Для текста в фигурных скобках напиши `{{note}`. В арте `{{` не помогает:
  измени текст в редакторе арта и снова переведи арт.
- Для `item.S` нужен пункт с клавишей `S` в том же экране.

### `{#if} has no {/if}`

```
screens/about.bbt:12:8: {#if} has no {/if}
```

Добавь `{/if}`. Блок кончается в том же файле, где начался.

### `control character U+0009`

```
screens/about.bbt:13:1: control character U+0009
```

В строке есть TAB. Замени его пробелами. Настрой редактор, чтобы клавиша Tab писала пробелы.

### Условие

```
screens/term.bbt:14:8: expected an integer or a string, found "xterm"
screens/term.bbt:14:38: integer field "term.colors" needs an operator
```

- `{#if term.type == xterm}`: пиши текст в двойных кавычках: `term.type == "xterm"`.
- `{#if term.colors = 256}`: сравнивай через `==`.

### `item: must be an array of tables`

```
screens/main.bbt:2:1: item: must be an array of tables
screens/main.bbt:5:2: table item already exists
screens/main.bbt:5:2: table item already exists as an array of tables
screens/main.bbt:5:3: key item already exists as a table, but should be an array table
```

Во front matter стоит `[item]`. Напиши `[[item]]`.
Первое сообщение выводит экран с одним пунктом. Остальные сообщения дают строку таблицы.

### `unknown screen`

```
screens/main.bbt:2:1: item "T": do: unknown screen "term"
```

Для `goto term` нужен файл `screens/term.bbt`. Создай файл или исправь имя.

### `screen has no items`

```
screens/x.bbt:1:1: screen has no items
```

Каждому экрану, кроме `goodbye`, нужен хотя бы один пункт. Добавь пункт.

### `not in the flat form`

```
screens/logo.ans:1:1: not in the flat form, convert it with velourbbs art import
```

Арт — это файл редактора арта. Переведи его (задача 7).

### Поле в арте меняет цвет

```
screens/size.ans:1:7: token "{w}" changes the foreground: 11 at col 7, 14 at col 9
```

У символов токена два цвета: 11 в столбце 7 и 14 в столбце 9.
В редакторе арта нарисуй весь токен одним цветом. Потом снова переведи арт.

### Результат

1. В строке 10 файла `screens/about.bbt` «Лампы» поставь `{!titel}` перед `«Лампа»`.
2. Выполни `velourbbs check`. Команда выводит:

```
screens/about.bbt:10:8: unknown style "titel"
```

3. Удали `{!titel}`. `velourbbs check` ничего не выводит.

Полные правила: [screen-render](../../specs/screen-render.md), раздел 3.1,
и [menu-nav](../../specs/menu-nav.md), раздел 6.

## Не в MVP

В BBS пока нет этих возможностей:

- списков и циклов (`#each`), строк списков в арте, поставщиков данных и условий в арте.
  В MVP условия есть только в файлах `.bbt`;
- меток (`{@<id>}`) и выбора пункта стрелками.
  Пользователь выбирает пункт только его клавишей;
- проверок доступа (`require`). Для них нужны пользователи;
- `ask` и токена поля в значении `args`;
- клавиш со знаками препинания, например `?`;
- подписи пункта. BBS не печатает текст пункта;
- кодов отображения других BBS-программ: pipe-кодов, `@`-кодов и MCI-кодов.
  Конвертера нет.

Полные правила: [bbt-format](../../specs/bbt-format.md), раздел 10.
