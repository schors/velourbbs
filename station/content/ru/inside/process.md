# Процесс

## Что делает

Velour пишут в основном AI-модели: спецификации, код, тесты и руководства.
Человек-оператор управляет работой и принимает решения.
Вся работа открыта: issues, pull request и ревью лежат в
[github.com/schors/velourbbs](https://github.com/schors/velourbbs).

## Как

### Задачи

Каждая работа - issue на GitHub. Тип issue задаёт её путь:

- `idea` - идея в очереди;
- `dev` - большая работа из нескольких блоков;
- `one-shot` - небольшая задача;
- `docs` - руководство для пользователей.

Этот раздел станции переписан в одной задаче `one-shot`.

### Гейты

Гейт - остановка, где работа ждёт ответа оператора.
На первом гейте модель показывает план и задаёт вопросы, а оператор выбирает.
Принятый план модель пишет в issue. Так решение принимает человек, и до кода.
Второй гейт - pull request. Мейнтейнер принимает его или пишет замечания.

### Сначала спецификация

Правила программы лежат в `docs/specs/`. Если код расходится со спецификацией,
спецификация меняется в том же коммите. Так у каждого правила одно определение.

### Тесты

Тесты проверяют каждую часть, которую можно проверить отдельно.
Перед каждым коммитом идут `go vet`, `go test` и `golangci-lint`.

Тест станции запускает `velourbbs check` на каталоге `station/`. Потом он снимает
каждый экран при 80x24 и 132x43 в 256 цветах и сравнивает снимок клеток с эталоном.
Эталоны лежат в git, поэтому каждое изменение экрана видно в pull request.
Ещё тест снимает бегущий свет и тиканье живых полей по кадрам.

### Ревью

Каждый pull request читают AI-ревьюеры. У каждого своя позиция: что проверять
и с какой точки зрения. Все отзывы модель публикует в pull request до первого исправления.
В каждой ветке отзыва она отвечает: исправлено или нет и почему.

## Что получает

- Открытую историю каждой правки: issue, план, ревью и ответы на них.
- Эталоны экранов, по которым видно каждое изменение станции.
- Коммиты, где каждая модель-автор записана соавтором.

## Ограничения

- Отзыв - только информация. Работу принимает merge, а его делает мейнтейнер, не модель.
- Модель работает с токеном оператора, поэтому её посты - посты оператора.
  Каждый пост модели начинается со строки `Agent: <модель>`.
