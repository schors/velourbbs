# Данные

## Что делает

Velour хранит данные станции в одном текстовом файле. СисОп читает и правит его
в текстовом редакторе.

## Как

Файл - JSON Lines ([jsonlines.org](https://jsonlines.org/)): UTF-8, одна запись -
один объект JSON на строке. Первая строка - заголовок с версией формата:

```
{"format":"velourbbs-store","version":2}
```

У каждой следующей записи есть вид, поле `kind`. Код описывает каждый вид: его поля, проверки и предел
числа записей. Когда записей больше предела, уходят самые старые.
Время - RFC 3339 в UTC, с секундами.

Velour держит все записи в памяти. Каждое изменение пишет файл целиком:

1. Проверяет новые записи.
2. Пишет их во временный файл `<файл>.tmp` с правами 600 и сбрасывает его на диск.
3. Переименовывает временный файл поверх старого. Это точка фиксации.
4. Сбрасывает на диск каталог.

## Что получает

- После сбоя на Linux или macOS в файле есть записи до изменения или после него, не их смесь.
- Ошибка до переименования оставляет старый файл и старые записи.
- Каждое изменение формата повышает версию. Миграции переводят старый файл в новую версию
  при чтении. Ошибка показывает строку файла.

## Ограничения

- Файл - не больше 16 МБ, ведь он весь лежит в памяти.
- Один файл - один `velourbbs serve`. Файл не блокируется.
- Правка файла, пока сервер работает, пропадёт при следующей записи.
- Старая версия Velour не читает файл новой версии. Перед выкладкой с миграцией
  сделайте копию файла.
- В Windows Go не делает переименование атомарным, и оно не проходит,
  пока файл открыт другой программой.
- Velour не берёт SQLite и bbolt: их файл не прочитать без отдельной программы.
  Ещё `modernc.org/sqlite` добавляет к программе 6 МБ и 10 модулей.
