# Go и библиотеки

Velour написан на Go. Это одна программа без cgo: она принимает гостей по telnet,
рисует экраны, хранит данные и проверяет файлы СисОпа.
Исходники открыты: [github.com/schors/velourbbs](https://github.com/schors/velourbbs).

## Почему Go

Язык выбрали 12 ноября 2026 года. Go сравнили с Rust, и четыре ревьюера
выбрали Go: Go-разработчик, Rust-разработчик, инженер по терминалам и протоколам
и специалист по безопасности. Сравнение лежит в `docs/specs/host-language.md`.

- Сеансы. Каждый сеанс - своя goroutine. Код читает и пишет блокирующими вызовами,
  а время ограничивают дедлайны `net.Conn`. В Rust сеанс - задача tokio с `.await`.
- SSH на будущее. В Go есть `golang.org/x/crypto/ssh` из проекта Go.
  В Rust есть `russh` от небольшой команды.
- Сборка. Go собирает статическую программу без cgo, быстро и с малым графом зависимостей.
  Rust собирает медленнее, а `build.rs` и процедурные макросы зависимостей выполняются при сборке.
- Терминал. Здесь языки равны: разбор арта, модель клеток, вывод изменений
  и декодер клавиш пишут сами в обоих языках.

## Где Rust сильнее

- Lua для модов. В Rust `mlua` ставит предел памяти каждому Lua-состоянию.
  У `gopher-lua` для Go такого предела нет. Моды на Lua пока только в планах.
- Готовые части для разбора терминала: `vte` и `vt100`.

## Библиотеки

Кроме стандартной библиотеки Go, у Velour три прямые зависимости:

- `go-toml/v2` читает настройки и экраны. С ней сравнили `BurntSushi/toml`.
  Выбрали `go-toml`: она даёт строку и столбец неизвестного ключа,
  поэтому `velourbbs check` показывает место ошибки.
- `displaywidth` делит текст на графемы и даёт ширину каждой по Unicode 17.
  С ней сравнили `uniseg` (Unicode 15) и `go-runewidth` (меряет руны, а не графемы).
- `goldmark/v2` читает Markdown: CommonMark 0.31.2 и таблицы GFM.
  У неё нет своих зависимостей. Версия 2 молодая, и патч может сломать API,
  поэтому версия закреплена в `go.mod`.

Журнал пишет `log/slog`, команды разбирает `flag`, данные кодирует `encoding/json`.

## Свой код вместо библиотек

- Telnet. Библиотеки Go не дают серверу NAWS и TTYPE с ограниченными буферами.
  Свой разбор - около 200 строк.
- PROXY protocol. У `go-proxyproto` API версии 0.x, а её выпуски 2026 года
  поменяли поведение по умолчанию. Свой приём версий 1 и 2 - около 200 строк.
- Вывод в терминал. `tcell` рисует весь экран как приложение, а Velour показывает
  страницы со строкой "Дальше". Ещё `tcell` не опрашивает терминал при подключении.
- ANSI-арт. Серверу нужны только стили SGR, а импорту - около 15 команд.
  Полный разбор терминала `charmbracelet/x/ansi` - большая зависимость.
- Условия на экранах. В их грамматике 7 правил. `expr` добавил бы арифметику
  и функции, которых в формате нет.
- Socket activation. Код читает две переменные окружения и вызывает `net.FileListener`:
  около 30 строк вместо `go-systemd`.

## Ограничения

- Свой код - это свои тесты и своё сопровождение. Каждое решение записано
  в разделе "Libraries" своей спецификации.
- В стандартной библиотеке Go и в `golang.org/x/text` нет деления на графемы.
  Поэтому ширину даёт сторонняя `displaywidth`.
