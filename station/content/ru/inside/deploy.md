# Выкладка

Новая версия станции выходит по тегу. Мейнтейнер ставит тег вида `v0.1.0`
на коммит из `main`. Дальше всё делает GitHub Actions.

## Сборка

Задание проверяет, что тег стоит на коммите из `main`. Потом оно запускает `go vet` и тесты
и собирает Velour для Linux, macOS и Windows.
Программы и их суммы SHA-256 попадают в GitHub Release.

## Доставка

Задание отправляет на хост по SSH один архив: программу, каталог `station/`,
юниты systemd и скрипт установки. Адрес хоста и ключ SSH лежат в секретах GitHub.
Журнал задания открыт всем, но секретов в нём нет.

## Установка

Скрипт на хосте сначала запускает `velourbbs check` на новой станции.
Если проверка находит ошибку, выкладка останавливается, и работает прежняя версия.
Потом скрипт переключает ссылку `current` на новую версию и перезапускает службу.

Файл данных лежит вне версий и остаётся после каждой выкладки.
Экран "О станции" показывает тег в строке "Версия Velour".

## Без потери подключений

Порт держит systemd, а не Velour. Во время перезапуска порт остаётся открытым:
новые подключения ждут в очереди, и их принимает новая версия.
Открытые сеансы показывают экран о перезапуске и закрываются.

## Откат

Чтобы вернуть прежнюю версию, мейнтейнер повторяет её запуск в GitHub Actions.
GitHub позволяет это 30 дней.
